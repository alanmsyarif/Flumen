# GPU Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a separate Warp/CUDA surface-particle workflow with continuous frame-based emission and measured Blender viewport performance.

**Architecture:** Keep simulation state and collision queries in fixed-capacity CUDA arrays. A Blender adapter coordinates integer frames and transfers compact display data to an instanced-drop host. Preserve existing Geometry Nodes workflows and their bakes.

**Tech Stack:** Python, Blender 5.2, NVIDIA Warp/CUDA, NumPy for bulk transfers, pytest outside Blender, unittest inside Blender.

**Spec:** [Approved GPU flow design](../specs/2026-09-30-gpu-flow-design.md).

## Global Constraints

- Windows, RTX 5050, 8151 MiB reported VRAM, driver 591.86; verify the actual runtime again during execution.
- Stationary collision meshes, meter-based world coordinates, identity water host.
- Defaults: continuous mode, 64 particles/frame, 8192 maximum live particles, 4-second lifetime, scene frame range for emission.
- Preserve existing gravity/radius/source-mask defaults and existing static/Geometry Nodes behavior.
- Integer-frame emission is inclusive at start/end; births have age zero and move on the following frame interval.
- Physics uses seconds with `dt = fps_base / fps`; GPU Flow never silently falls back to CPU.
- No package installation at registration, per-particle Blender objects, or serialization of CUDA pointers.
- Real-time acceptance: at least 30 FPS, total frame p95 <= 33.3 ms after JIT/setup, 1920x1080 solid viewport, approximately 20,000-triangle sphere, 600 sequential frames, no dropped simulation steps.
- This plan delivers increment 1. Connected films/rivulets and moving surfaces remain follow-on work; particle playback alone is not visual completion.

## Review Focus

1. NaN/invalid settings and excessive requested births must fail validation or remain bounded without allocation spikes (Tasks 1, 3).
2. Mirrored/nonuniform source transforms, degenerate triangles, and empty source masks must produce correct world-space geometry or a clear rejection (Task 2).
3. Duplicate hosts, callback recursion, and undo must not share or double-step runtimes (Task 6).
4. Non-unit `fps_base`, skipped frames, and seeks before simulation start must preserve frame-based emission and physical elapsed time (Task 5).
5. Missing wheels, native-library failures, and GPU memory allocation failure must leave existing workflows usable and release partial resources (Tasks 1, 6, 8).

## Files and shared interfaces

New numerical modules: `flumen/gpu/{__init__,config,device,source,state,emission,motion,solver}.py`. Keep `__init__` free of eager Warp imports. No module in this package imports `bpy`.

New Blender modules: `flumen/gpu_properties.py` (settings), `gpu_runtime.py` (host registry/frame lifecycle), `gpu_display.py` (bulk geometry/instances), `gpu_operators.py` (create/reset), `gpu_ui.py` (GPU panel). Modify `flumen/__init__.py` only for registration/lifecycle; existing solver modules remain unchanged.

Shared types, defined by their owning tasks:

- `FlowConfig` (Task 1): validated immutable emission, physics, and capacity settings; plain Python values.
- `DeviceInfo` (Task 1): device alias/name, driver and Warp versions; CUDA verified.
- `SourceMesh` (Task 2): world-space float32 vertices, int32 triangles, island IDs, source sampling tables, plus owned Warp mesh resources; `close()` releases ownership.
- `ParticlePool` (Task 3): fixed GPU arrays, monotonic int64 IDs, counters, and volume ledger; `close()`.
- `DisplayBatch` (Task 3): contiguous NumPy positions `(N,3)`, radii `(N,)`, IDs `(N,)`; only active particles.
- `FrameStats` (Task 3): frame/live count; requested/accepted/capacity-rejected/source-rejected births; emitted/live/removed volume; substeps/travel-limited count; synchronized solver/transfer milliseconds.
- `FlowSolver` (Task 5): owns config, source, and pool; `seek(frame: int) -> FrameStats`, `snapshot() -> DisplayBatch`, `reset() -> None`, `close() -> None`. Construction takes `config`, `source`, `device`, `start_frame`, `fps`, `fps_base`; starts with no evaluated frame.
